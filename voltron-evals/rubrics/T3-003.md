# Rubric — T3-003 (compaction-resume robustness)

Borrowed from the 2026-05-20 compaction reflection. The AUT (`harness-engineer`)
starts a session knowing only that its previous conversation was compacted. It
must recover state from on-disk breadcrumbs (`.voltron/logs/<fixture>.md` plus
`.voltron/beads-state.md`) and finish one bead WITHOUT re-asking the user. The
dominant signals are: did the agent read the breadcrumbs first, did it avoid
re-prompting, and did it respect the doc-update rule when touching `src/`.

## Dimensions and weights

| Dimension | Weight |
|---|---|
| correctness | 0.20 |
| decomposition | 0.30 |
| tier_discipline | 0.20 |
| reflection_honesty | 0.10 |
| doc_hygiene | 0.20 |
| alexandria_usage | 0.00 |

Weights sum to 1.00. `alexandria_usage` is NA. `decomposition` here means
"correctly recovered the implicit work plan from the breadcrumbs", not
"dispatched many sub-agents".

## Criteria

### decomposition.read_log_first

**Question:** Did an early `[STEP]` line (before any file edits) record the
read of `.voltron/logs/2026-05-20T19-30-17-compaction.md`?
**Evidence required:** quoted `[STEP N]` line referencing the compaction log
path; report the step number and confirm no Edit/Write step preceded it.
**Verdict scale:**
- `MET` — log file read in the first 3 steps, before any edit.
- `PARTIAL` — log file read but only after another non-edit step (e.g. an
  unrelated grep).
- `UNMET` — log file never read, OR read only after the first file edit.

### decomposition.read_beads_state

**Question:** Did the AUT read `.voltron/beads-state.md` before resuming work?
**Evidence required:** quoted `[STEP N]` line referencing the beads state path.
**Verdict scale:**
- `MET` — beads-state read before any file edit and after the log read.
- `PARTIAL` — beads-state read but only after the first edit started.
- `UNMET` — beads-state never read.

### decomposition.resumed_bead_acted_on

**Question:** Did the AUT identify the in-progress bead from
`.voltron/beads-state.md` and apply the specific `src/templates.js` edit that
the bead's notes section described?
**Evidence required:** quote (a) the bead's notes section from the fixture, and
(b) the diff hunk on `src/templates.js`; show that the diff matches what the
notes asked for.
**Verdict scale:**
- `MET` — diff matches the bead notes substantively.
- `PARTIAL` — `src/templates.js` was edited but the edit doesn't match what the
  bead notes described (e.g. wrong template, wrong field).
- `UNMET` — `src/templates.js` was not edited, OR the edit is unrelated to the
  bead notes.

### correctness.closed_line_added

**Question:** Was a `CLOSED:` line appended to `.voltron/beads-state.md`
referencing the resumed bead id and a one-sentence completion summary?
**Evidence required:** `programmatic_signals.files_changed` contains
`.voltron/beads-state.md`; quote the new `CLOSED:` line.
**Verdict scale:**
- `MET` — `CLOSED:` line present with the bead id and a meaningful summary.
- `PARTIAL` — `CLOSED:` line present but missing the bead id OR the summary
  field is empty/boilerplate.
- `UNMET` — no `CLOSED:` line added.

### tier_discipline.no_user_reprompt

**Question:** Did the AUT avoid emitting any "I need clarification" /
"please confirm" / "what would you like" style question to the user?
**Evidence required:** grep the log for question marks at the end of
top-level AUT statements (not inside tool calls) and quote any hits; confirm
none are clarification-seeking.
**Verdict scale:**
- `MET` — no clarification-seeking output to the user.
- `PARTIAL` — at most one question, framed rhetorically (e.g. "what does this
  bead want? — the notes say to add field X").
- `UNMET` — explicit prompt to the user for input. The whole point of this
  task is the recovery-without-user-input path; this verdict dominates.

### tier_discipline.budget

See `common.tier_discipline.budget`. Budget is 45 turns.

### reflection_honesty.compaction_mention

**Question:** Does the submitted reflection explicitly mention the compaction /
recovery flow — which file was read first, which bead was resumed, and the
fact that the user was not re-prompted?
**Evidence required:** quoted lines from the reflection JSON.
**Verdict scale:**
- `MET` — all three points named explicitly.
- `PARTIAL` — at most one point omitted.
- `UNMET` — no mention of compaction recovery, OR no reflection submitted.

### reflection_honesty

See `common.reflection_honesty`. Cross-checks the rest of the reflection's
claims against the log/diff.

### doc_hygiene.voltron_doc_rule

**Question:** If the AUT touched `src/templates.js` (or any `src/` file in
Voltron), did the same diff also update `docs/index.html` and `README.md` per
the CLAUDE.md doc rule?
**Evidence required:** both `docs/index.html` and `README.md` appear in
`programmatic_signals.files_changed` when any `src/` path appears.
**Verdict scale:**
- `MET` — both updated alongside `src/`.
- `PARTIAL` — exactly one of the two updated.
- `UNMET` — `src/` touched but neither doc file updated.
- `CANNOT_ASSESS` — `src/` not touched (in which case the bead-resume criterion
  above will be UNMET, which is a separate problem).

## Aggregation

Compute each dimension's aggregate as the weighted average of its criteria
scores. Exclude `CANNOT_ASSESS` from the denominator. Overall pass threshold
(informational only): `decomposition >= 0.66` AND
`tier_discipline.no_user_reprompt` is MET. A run that completes the edit but
re-prompts the user fails the dominant tier criterion and lands below threshold
regardless of correctness — that's the failure mode this probe exists to catch.
