## 3. Prioritized Actionable Improvements

### Priority 1 — Strong signal, broad impact

#### P1-A: fullstack-dev — commit-budget exhaustion hard rule
- **Template:** `fullstack-dev` in `src/templates.js`
- **Evidence:** 3 reflections (2026-06-03, 2026-06-08, 2026-06-10)
- **Problem:** Agents pass all validators but then re-run them at the commit step, exhausting max_turns. The commit never happens.
- **Suggested change (verbatim from 2026-06-03):** "Add a hard rule in the fullstack-dev template: when you reach the commit step with max_turns ≤ 5 remaining, stage files but DO NOT run validators again — emit a handoff to committer with the exact file list."
- **Additional signal (2026-06-08):** Same pattern on transport task — work was fine but agent got cut mid-loop.
- **Additional signal (2026-06-10):** "[DONE] line sometimes didn't surface in the trail despite success."

#### P1-B: committer — cap post-commit self-validation
- **Template:** `committer` in `src/templates.js`
- **Evidence:** 2 reflections (2026-06-03, 2026-06-08)
- **Problem (2026-06-08):** "When given 4-5 post-commit validation greps, it consistently exhausts its turn budget AFTER the commit already succeeded and exits non-zero (max_turns), producing a false-negative FAILED status the orchestrator has to reconcile manually."
- **Problem (2026-06-03):** "Initial Task 3 recovery attempt only got 2 steps in before exit — appeared to be turn-budget exhaustion on typecheck output size."
- **Suggested change (2026-06-08):** "Cap committer self-validation at 2 cheap checks (`git log -1` + `git status --porcelain`), or have it emit [DONE] immediately after the commit and treat validation as best-effort so a successful commit never reports as failure."

#### P1-C: pr-opener — GH_TOKEN pre-flight check
- **Template:** `pr-opener` in `src/templates.js`
- **Evidence:** 3 reflections (2026-06-05 15:58 `devops-engineer`, 2026-06-05 17:07 `overall_notes`, 2026-06-05 21:47 `pr-opener`)
- **Context:** The Dockerfile GH_TOKEN passthrough was implemented in v3.13.0 (PR #44, now merged). The remaining gap is the agent template itself.
- **Problem (2026-06-05 15:58):** "Container image lacks gh CLI for PR-opening tasks... Any push or PR operation requires either a credential helper or a PAT env var — neither is present."
- **Problem (2026-06-05 17:07, overall_notes):** "Capability gap confirmed for the 3rd time: every dispatch for branch-manager/pr-opener/deploy-trigger had to be routed through the user."
- **Suggested change (2026-06-05 21:47, pr-opener):** "The pr-opener template should instruct the agent to check for GH_TOKEN/gh auth at start and emit a clear handoff if absent." Also: document that pr-opener/branch-manager are host-auth-dependent and will fail silently without the token.

#### P2-E: csharp-dev — WebGL runtime-branch pattern
- **Template:** `csharp-dev` in `src/templates.js`
- **Evidence:** 1 reflection (2026-05-26 unity)
- **Problem:** "The WebGL Considerations section shows the `#if UNITY_WEBGL && !UNITY_EDITOR` compile-guard pattern but does not show the runtime-branch pattern (`Application.platform == RuntimePlatform.WebGLPlayer`)."
- **Suggested change:** "Add a short subsection under 'WebGL Considerations' titled 'Compile-time vs runtime platform gating' that contrasts `#if UNITY_WEBGL` (strips code from the WebGL build entirely) with `if (Application.platform == RuntimePlatform.WebGLPlayer)` (single binary, branches at runtime), and notes that `File.*`/`Stream`/`Thread`/`Socket` APIs throw `PlatformNotSupportedException` at runtime on WebGL regardless of compile guard."
