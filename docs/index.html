Docker Execution

The scrum-master launches each specialist agent inside a Docker container with --dangerously-skip-permissions via the run_agent_in_docker MCP tool. You run Claude Code normally on your desktop — Docker is handled behind the scenes.

🎯
Scrum-master creates a work plan Plans tasks, assigns agents, registers progress. Checks that Docker is available and Dockerfile.voltron exists.
↓
🐳
Calls run_agent_in_docker for each task The tool builds the image (cached), mounts the project + OAuth credentials, composes the prompt from the agent template + CLAUDE.md + task description, and launches Claude Code inside the container.
↓
⚡
Agent executes autonomously Inside Docker with --dangerously-skip-permissions — creates files, runs tests, fixes errors, iterates — with zero manual approval prompts. File changes are visible on the host via volume mount.
↓
✅
Output returned to scrum-master Scrum-master reviews the result, updates progress, and proceeds to the next task. Dashboard auto-refreshes every 5 seconds to reflect each transition.
Why Docker? Docker provides OS-level isolation from your host system, making --dangerously-skip-permissions safe to use. Agents can create files, run tests, install packages, and iterate on errors without any human gating — while your host stays protected.
No workflow change needed Run Claude Code normally on your desktop. The scrum-master handles Docker automatically — just ensure Docker is installed and running, and Dockerfile.voltron exists (generated by scaffold_project).

The Agent Teams

Scaffold the right team for your project type. Every project gets a scrum-master coordinator.

Core — all projects

Scrum Master @agent-scrum-master

Reads backlogs and project plans, breaks work into agent-sized tasks with dependencies and acceptance criteria. Never implements — only plans and delegates. Uses beads (bd ready --json) for dependency-aware task orchestration when available.

Project Planner @agent-project-planner

Researches tech stacks, designs architecture, defines data models and API contracts. Produces comprehensive project plans for scrum-master to decompose.

Researcher @agent-researcher

Deep research specialist. Finds any information — technical docs, APIs, pricing, competitors, legal text, community consensus — using web search, live page navigation, and structured extraction.

Unity

Scene Architect @agent-scene-architect

GameObject hierarchy, prefabs, scene composition, transforms, and components. Requires live Unity Editor — invoke directly from the chat window, not via Docker.

C# Dev @agent-csharp-dev

MonoBehaviours, ScriptableObjects, gameplay systems, and editor tools. Writes clean, performant Unity C#. Docker-compatible for file editing; defers compilation verification to build-validator.

Shader Artist @agent-shader-artist

Shaders, materials, VFX Graph, post-processing, and render features. Knows URP, HDRP, and Built-in. File editing in Docker; visual preview requires direct invocation.

Build Validator @agent-build-validator

Console monitoring, compile checks, Play Mode smoke tests, pre-commit validation. Requires live Unity Editor — invoke directly from the chat window, not via Docker.

Asset Manager @agent-asset-manager

Folder structure, import settings, naming conventions, and project audits. Folder/manifest work in Docker; import settings require direct invocation.

Web / Fullstack

Fullstack Dev @agent-fullstack-dev

React/TypeScript frontend and Node.js/Express backend. Handles components, APIs, hooks, and data flow.

DevOps Engineer @agent-devops-engineer

Terraform, CI/CD pipelines, Docker, Fly.io, and AWS. Infrastructure as code and deployment automation.

UI Designer @agent-ui-designer

CSS architecture, responsive and mobile-first layouts, theming, PWA manifests, and accessibility.

QA Tester @agent-qa-tester

Vitest/Playwright tests, Lighthouse audits, bundle size analysis, and quality gates before merging.

Tier-1 Coordinators v3.1 new

Two specialist coordinators join scrum-master at Tier 1.

code-analyst

Directs all 11 Inspect-layer micro-agents to audit a codebase — coverage gaps, dead code, API shapes, dependency health. Produces persisted reports in .voltron/analyses/. Invoke before non-trivial implementation work.

doc-writer

Owns all prose documentation — README, CHANGELOG, ADRs, API reference, Mermaid diagrams. Dispatches adr-writer, api-doc-generator, and diagram-maker. Writes end-of-session recaps.

Dynamic Model Selection v3.5 new

Voltron assigns each agent a default model tier. Override per-invocation when higher quality or speed is needed.

Opus Coordinators & Planners · 5 agents

Highest capability. Used by scrum-master, project-planner, code-analyst, doc-writer, and reflection-processor. Reserved for orchestration and complex reasoning.

Sonnet Sub-managers & Specialists · 16 agents

High capability at moderate cost. Used by domain sub-managers (fullstack-dev, devops-engineer, csharp-dev, etc.) and specialist coordinators.

Haiku Micro-agents · 53 agents

Fast and cost-efficient. Used for focused single-verb tasks: Inspect, Write, Validate, and Publish layer micro-agents that each do one thing on one file or API.

Override per-invocation: Pass model: "sonnet" or model: "opus" to run_agent_in_docker / start_agent_in_docker to retry a failed or low-quality micro-agent at a higher tier. Sub-managers are instructed to do this automatically when a micro-agent output is unsatisfactory. The list_templates tool shows each agent's default model tier.

Stringer Integration v3.2 new

Persistent codebase baseline for smarter analysis. Build once, read cheap every session.

stringer-baseline-builder

Runs stringer scan and saves a structured baseline to .voltron/stringer/baseline.json. Skips gracefully if stringer is not installed. Run once on project setup; refresh when prompted (every 14 days or 50 commits).

stringer-delta-reader

Reads the baseline and runs a cheap stringer --delta check each session. Reports what changed since the baseline, whether a refresh is needed, and surfaces new signals as structured findings.

How it works: setup_voltron auto-detects stringer and registers its MCP server (stringer mcp serve) in ~/.claude.json. The code-analyst coordinator reads the baseline before dispatching Inspect-layer agents, giving every analysis a free head start on what changed.

Install via APM v3.3 new

One command deploys all 63 agents + MCP server registration using the Agent Package Manager.

# Install APM (once)
pip install apm-cli

# Deploy Voltron to Claude Code (any project)
apm install 7ports/project-voltron

APM automatically deploys all agent .md files to .claude/agents/ and registers the Voltron MCP server in ~/.claude.json. Claude can run this command on itself. The apm.yml manifest is always kept in sync with the latest agent set — when new agents are added to Voltron, run apm update 7ports/project-voltron to get them.

The classic setup_voltron MCP tool remains the primary setup path and works without APM. APM is an additional convenience for users who prefer a CLI-first workflow.

Quick Start

Three steps from zero to a full agent team in your project.

1

Setup

Clone and run the one-command setup:

git clone https://github.com/7ports/project-voltron.git
cd project-voltron
node scripts/setup.js

Installs dependencies, registers the MCP server, and configures the global allowlist automatically. Restart Claude Code when prompted.

2

Scaffold

In any project, ask Claude Code:

"Scaffold this Unity project with Voltron agents"
"Scaffold this web project with Voltron agents"
"Scaffold this project with Voltron agents"

Agent files are written directly to disk — no manual copy-paste required.

3

Develop

Fill in CLAUDE.md, then invoke agents:

@agent-scrum-master      ← plan your sprint
@agent-fullstack-dev     ← React/TypeScript + Node.js
@agent-csharp-dev        ← Unity C# scripts
@agent-devops-engineer   ← CI/CD, Docker, infrastructure

Self-Improving Agent Templates

Voltron gets better with every session through a built-in feedback loop.

Session runs with voltron agents scrum-master coordinates; specialists execute
↓
Reflections submitted automatically scrum-master submits at phase completion, blockers, and session end — per-agent feedback with suggested changes
↓
Reflections accumulate in reflections/ structured JSON, tied to project type and agents used
↓
GitHub Actions runs Mon/Wed/Fri The reflection-processor agent (Sonnet 4.6) groups feedback by agent, prioritizes by frequency, applies targeted template edits, and opens a PR
↓
PR reviewed and merged human reviews the diff before it reaches main — version bumped in package.json
↓

Alexandria Integration

Voltron agents are paired with Project Alexandria — a shared tooling knowledge base — so setup knowledge accumulates across every session.

scrum-master plans a new project calls get_project_setup_recommendations from Alexandria to surface required tools before work begins
↓
specialist agents set up tools call quick_setup before installing anything — mandatory, not optional. Agents follow battle-tested guides rather than improvising from training data
↓
agents discover platform-specific fixes call update_guide after completing integrations — workarounds, version notes, and gotchas flow into Alexandria
↓
knowledge is available to every future agent the next project that touches the same tool gets accurate, up-to-date guidance automatically
